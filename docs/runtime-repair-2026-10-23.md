# 运行审计修复（2026-10-23）

本次修复围绕实际运行、重启和邮件入账。保留旧事件的数值语义，不补造历史互动质量；不增加生产依赖，MIME 解码独立实现，沿用项目 MIT 许可。

| F09 同一原信仅接受首次回复 | 按每封回信身份去重，允许同一 In-Reply-To 的不同回复；无 Message-ID 时用 UIDVALIDITY + UID。 |

## 升级与旧快照恢复

1. 停止旧引擎，备份数据库。不要同时运行新旧版本。
2. 安装锁定依赖（`npm ci`），部署修复代码。`migrate()` 会幂等执行 `003_mail_inbox.sql`；也可由部署流程先执行 `migrations/*.sql`。
3. PostgreSQL 模式启动总是全量对账。通过后追赶当前时刻并持久化 tick 边界，再开放服务。
4. 如果旧快照因未记录 tick 历史而分歧，保持引擎停止，使用同一数据库连接运行：

```bash
npm run recover
```

默认只读，显示旧快照和规范事件重放的 hash、恢复时刻、预览 token。无原点或无快照会拒绝猜测。检查备份与预览后，可显式执行：

```bash
npm run recover -- --apply <preview-token> --reason "reviewed legacy tick drift; database backed up"
```

这一步选择**按现存事件重放的状态**。旧版未记录的时间切分和随机数调用次序不可逆推，因此恢复后的数值可能不同。工具检查预览是否已过期，写入恢复审计、tick 边界及新快照；不删除旧快照和事件。它持有与引擎相同的单写者锁，活实例未停止时拒绝运行。完成后重启并确认启动对账通过。

升级开始出现 `409 可选活动未获许可或预算不足` 是门控生效。B_daily / M_min 仍须经过已有参数变更流程标定，不能为消除错误而任意放宽。

## 验证边界

- 本地：类型检查通过，334 项测试通过；15 项 PostgreSQL 测试由 CI 在真实 PostgreSQL 16 上执行。本地无 PostgreSQL。
- `npm audit --omit=dev`：本次检查为 0 个已知漏洞。
- 邮件协议、崩溃恢复与重复回复使用脚本化 socket；没有发送真实邮件，也没有使用生产凭据。
- SMTP 接收成功到本地记录成功之间仍存在崩溃窗口；邮件提供商不支持与本地数据库事务绑定，不能承诺恰好一次投递。遇到投递结果不明，应核对 Message-ID 与提供商记录。
- 收信未知 contingency 仍是 unknown。普通邮件/MCP 文本不会自动获得测量分数，现有旁路测量不参与 fold；印刻和依恋增长所需的测量接线是既有设计缺口，本次没有伪造估值来掩盖它。
- 本次修复不代表生产实例已升级；数据库恢复与真实邮件连通性需在部署环境验证。
